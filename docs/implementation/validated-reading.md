# Validated reading stage

Stage 2 of [the accepted delivery sequence](https://github.com/adellorto/normattiva-mcp/issues/6#issuecomment-5992182865), based on [structured-source selection](https://github.com/adellorto/normattiva-mcp/issues/11#issuecomment-5991636304) and [the accepted indexing prototype](https://github.com/adellorto/normattiva-mcp/issues/17#issuecomment-5991117806).

## Shared interfaces

`ActTraversal` exports `actLocator(publication)`, `listArticles(input, signal?)`, `readArticle(input, signal?)`, `readAct(input, signal?)` and `evict()`. Inputs/results use the coordinated schemas from the groundwork. `registerTraversalTools(server, reader, context)` exercises these focused replacement tools at the MCP seam. The default servers still register the existing public interface: shallow discovery, production registration, prompts/resources, migration documentation and release checks belong to the subsequent delivery stages. This commit does not publish a replacement public API or claim release acceptance.

Example application setup:

```ts
const upstream = new UpstreamRuntime();
const reader = new ActTraversal({
  signingKey: Buffer.from(configuredHexKey, "hex"),
  upstream,
});
registerTraversalTools(server, reader, { upstream });
```

Preserve a cryptographically generated key of at least 32 bytes in deployment configuration. Compatible processes with the same key can use the same signed article/attachment references and cursors. A different/lost key rejects existing references; there is no silent restart and no universal package secret. `a1_` publication locators are portable validated publication values, not proof of existence. `n1_` references are bounded, versioned, HMAC-SHA256 authenticated payloads. They carry publication, frozen date, supplied official source, representation SHA256 (AKN byte digest plus supplied navigation/address crosswalk), operation/position or occurrence/address/content fingerprints. Direct-only article continuations bind the actual acquired official detail endpoint and its content, without inventing an unacquired AKN address. Changing interpretation/position semantics requires a reference-format revision.

## Verification and continuation

Acquisition starts at the unique dated publication ELI page and follows its actual AKN link. Hosts, identity and link parameters are validated; redirects are separate counted attempts and cannot leave the official website. The XML must identify the publication and a compatible edition/component expression. These dates do not themselves certify historical correctness. Before emitting each readable occurrence, a separate dated detail read must agree on Gazette identity, editorial code, heading (for articles), validity interval and legal content. All supplied coordinate fields, including layer, group, suffixes, extended suffix and version, are retained. No attachment ordinal is derived from XML component sequence.

The sidebar supplies addresses, never historical membership. Ordered AKN occurrences preserve readable hierarchy, component ancestry and repeated eIds/labels. Repeated labels require a complete ordered crosswalk of distinct supplied addresses and per-occurrence detail verification. Unknown structure fails explicitly. Conflicting component headings remain listed as unresolved component references with withheld content; graphics are identified and linked without scan interpretation or a historical-link claim. Unresolved components prevent complete inventory/absence claims. Notes-only agreement is allowed only when the difference is confined to the paired AKN `authorialNote` / website `note-akn` explanatory sections; both original copies retain their notes, and the selected copy is disclosed. Unclassified notes and substantive changes are conflicts. Lexical normalization is limited to whitespace, article heading spelling/punctuation and the typography equivalents reproduced by saved controls (`e'`/`è`, `avra'`/`avrà`, `procedera'`/`procederà`); it does not map disagreeing Latin suffixes.

Initial pages can be `pending` after bounded source preparation, or `more` while occurrence verification continues. Verification/reading interruptions preserve the exact returned prefix and first unfinished position. Every continuation receives a fresh shared call allowance, reacquires an evicted source and checks the exact representation digest/address, without switching sources. Direct article references contain the verified address and content fingerprint: even a fresh process performs one healthy detail request without index reconstruction. Notes changes during an article continuation cannot switch the content being traversed.

Completeness stays false until the entire supported inventory has been verified; traversal completion is independent of unread content. Unmatched sidebar addresses leave membership unresolved, including historical pages with future entries; they cannot establish absence or complete coverage. Reading a conflicting candidate against an acquired inventory returns unresolved. Unmatched nonarticle navigation components remain visible as unread attachment references, with the supplied official link and no verified historical-membership claim. Changes to supplied addresses or these components invalidate continuation even when XML bytes stay unchanged. Body text/graphics outside article occurrences and unknown outer-section structures fail explicitly. Known preface, preamble and conclusion sections are validated structurally but currently lack independent reading/address controls, so legal-content coverage explicitly excludes them; graphics in those sections are exposed as unread component references. Absence uses a completed verified inventory already acquired by the caller; an ambiguous direct failure remains unresolved when that positive evidence is unavailable. Throttling and generic failures retain their typed operational errors. Unread attachment references in coverage are the references displayed on that page; incomplete global coverage and its explanation remain visible on every page, avoiding an unbounded envelope.

Independent detail verification compares table dimensions, row/column coordinates, spans, header assignments and the legal values assigned to each cell; matching flattened text cannot excuse a structural conflict. Exact article references retain this structural fingerprint across restart. Plain-text article reads with tables return unresolved with guidance to use `read_act`; graphic article reads remain unresolved rather than silently omitting unread content. Reading splits inside text and table cells. Table IDs, row/column coordinates, spans, headers, total dimensions and absolute offsets survive pagination. Character budgets count Unicode code points; offsets address UTF-16 string positions, and chunks never split surrogate pairs. Both MCP representations, metadata, explanation and cursor count toward 128 KiB. An unrepresentable entry fails explicitly. Source reception stops at 24 MiB; XML rejects DTDs, malformed input, excessive node/depth/cell counts and unsupported nested tables. Automatic exports, full-history fallback and scan interpretation remain excluded.

## Runtime bounds and evidence

One process-wide preparation lane serializes decoded bodies and parsing, in addition to the existing fair upstream-attempt lane. Queueing and worker cancellation share the caller's deadline. Completed preparations can be reused by queued callers; no cancelled caller's in-flight upstream work is borrowed by another caller. XML parsing projects identification and legal structure, reduces each closed occurrence to segments, and releases its tree. A disposable worker enforces a 96 MiB old-generation / 4 MiB young-generation heap ceiling; parser failure/termination is explicit. The completed parsed cache holds at most 8 entries and 32 MiB of serialized content by default; eviction is optional for correctness. Source size is not a promise of support for every possible 24 MiB document.

Run `pnpm test` for deterministic shared-module, MCP, stdio and Streamable HTTP regressions. `node packages/core/test/fixtures/traversal-memory.mjs` measures the production TypeScript pipeline in an isolated process with streamed captured source bytes. On Node 24.15.0 / Linux on 5 October 2026, the revised pipeline measured 216,184 KiB peak RSS (about 211 MiB), 6 upstream fixture attempts, three queued preparations and two direct useful reads, including eviction/fresh-reader recovery; preparation took 1,268 ms. The final review-fix replay measured 212,928 KiB (about 208 MiB) with the same six attempts; preparation took 3,212 ms. Earlier whole-tree/main-heap controls exceeded the target (330,016 KiB in a streaming replay; fixture-heavy replays reached 423,428 KiB). Those failures drove streaming portal parsing, per-occurrence XML reduction and a bounded parser worker. Measurements are offline fixture results, not hosted deployment or upstream latency benchmarks. The memory regression asserts the 256 MiB ceiling in an isolated process; timings are observations, not thresholds.
