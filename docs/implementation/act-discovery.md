# Shallow act discovery stage

Stage 3 of [the accepted delivery sequence](https://github.com/adellorto/normattiva-mcp/issues/6#issuecomment-5992182865), tracked by [Implement shallow act discovery and resumable search](https://github.com/adellorto/normattiva-mcp/issues/20). The [act-discovery decision](https://github.com/adellorto/normattiva-mcp/issues/3) and [accepted routing prototype](https://github.com/adellorto/normattiva-mcp/issues/18) remain the design authority.

## Interface and routing

`ActDiscovery({signingKey, upstream?})` exports `findActs({request}, signal?)` and `continueActs({cursor}, signal?)`. `registerDiscoveryTools(server, finder, context)` registers `find_acts` and `continue_acts` at the MCP seam. The default stdio and HTTP registrations migrate together in stage 4; this stage is usable through the shared exports and staged registration. No package release or deployment is performed here.

```ts
const finder = new ActDiscovery({ signingKey, upstream });
registerDiscoveryTools(server, finder, { upstream });
const page = await finder.findActs({ request: "Cosa dice l'articolo 52 del CAD?" });
// Pass the selected candidate's act_locator and the separate article_reference
// to the explicit reading interface. Discovery never retrieves article text.
```

The bounded deterministic parser accepts complete type/number/year citations, supported abbreviated act types, Italian full issuance dates, reviewed common names, acronyms, article references including suffixes and a comma, topical requests, explicit ISO/Italian publication or issuance windows, a concrete date of vigenza, and version classes. Short citation years use conventional 1950–2049 expansion and must not exceed the current year; use four digits when a century is uncertain. Unsupported/incomplete citations, contradictory common-name coordinates, impossible/reversed dates, relative research dates, combined exact/date/status requests and reconstructed continuation instructions fail locally and require a clearer request. This is a bounded grammar, not a general language interpreter. It preserves the original request in `interpretation`; it does not guess silently among incompatible citations.

Complete citations use advanced exact search and verify returned type, year, number, publication and, when supplied, issuance date. Zero matches never relax into a topical search. One exact match can be `identified`; multiple matches remain `candidates`. The reviewed version-1 alias seed comes from Normattiva's [Costituzione e Codici](https://www.normattiva.it/staticPage/codici) page, plus a separately reviewed official TUEL citation. Every selected alias is verified through live exact search, including the issuance date in its reviewed URN, and includes provenance, review date and that URN. The seed is deliberately small and editable only after review; it is not model memory or an exhaustive dictionary. Change the alias version when modifying a reviewed mapping so older cursor plans cannot silently change meaning.

Alias review and exact search establish identity, not current legal force. All candidates currently report `current: "unknown"`; this stage emits no supersession claims without fresh official status evidence. Multiple procurement generations and requests for current or historical alias context remain explained candidates. A bare historical context such as “CAD nel 2018” does not become an act-year filter. Explicit date/status research is a separate validated advanced route. Basic topics use the official simple endpoint's observed, undocumented relevance ordering. Type/year and date/status filters use documented advanced search with chronological ordering.

## Continuation and failure behavior

The default page contains at most five candidates; internal configuration may select one through twenty. Public inputs remain one request or one literal cursor. Both MCP representations, metadata and cursors count toward 128 KiB UTF-8; candidate selection reserves 2 KiB for interruption details. Byte-limited pages can resume within an upstream page without dropping a candidate. An individually unrepresentable candidate fails explicitly. Requests whose full interpreted plan cannot fit the 16 KiB reference ceiling are rejected before upstream work.

`d1_` cursors contain the version, operation, alias version, interpreted plan, ordering/fallback choice, next alias target, upstream page and within-page offset. HMAC-SHA256 integrity uses the same preserved, configurable key requirements as reading references. Existing `n1_` signing semantics remain unchanged. No cursor database, per-process key or search cache is needed. A fresh compatible process resumes the plan without reparsing it into a new query. Wrong trust, tampering, wrong formats/operations and mixed continuation inputs fail explicitly. Within-page cursors also bind the returned page digest; a changed page requires a new request instead of silently shifting position.

Search is a live corpus. Across different upstream pages, ranking and membership may change between calls; `complete` describes the observed traversal and cannot prove exhaustive relevance or legal absence. Relevance HTTP 404, 405 or 501 at the initial position is specifically classified as endpoint unavailability and permits disclosed chronological fallback. There is no fallback for 400/422, 429, malformed successes, generic failures, exact misses, or after relevance traversal has begun. A degraded cursor retains its chronological route. Missing pagination fields, contradictory totals, duplicate publication identities and mismatched exact results are malformed operational responses.

All requests use the shared fair upstream lane, deadlines, cancellation and composed attempt allowance. Planned attempt exhaustion after useful candidates returns `more`; each continuation receives a fresh allowance. Unexpected failure before useful candidates is a typed error. Failure after useful candidates returns `interrupted` with the exact successful prefix, first unfinished position, and resumable cursor. This includes alias verification across generations. No internal preparation is labeled useful progress.

## Evidence and remaining delivery gates

Before this stage, `pnpm test` passed all 56 existing tests at `3f75ff5` on 5 October 2026, including the source parser's isolated 256 MiB memory gate. The discovery tests retain red-capable regressions for routing, local rejection, continuation, fallback, currentness uncertainty, full-date verification, byte caps and interrupted prefixes. All 28 requests from the accepted routing prototype replay through the production discovery seam; these are deterministic planner tests, not new model evaluations. Staged stdio and stateless Streamable HTTP fixtures exercise the same discovery output and typed-error contracts, including literal continuation in fresh servers.

The [fixture manifest](../../packages/core/test/fixtures/discovery/README.md) records four small, paced official-source captures made on 5 October 2026 and their limitations. They verify the sampled source shapes, alias citations and observed ordering; no frozen result-count or permanent relevance guarantee is inferred. Final tokenizer/guidance measurements, supported model/client runs, runtime distributions, configured hosted/npm portability, deployed official-surface canaries and package/release acceptance remain stage 5. Stage 4 still owns the default public registrations, trust configuration, prompts/resources, migration notes and smoke workflow.

The two-axis code review found no standards breaches and six specification defects in the first implementation: incomplete citation routing, reversed negated status, lost spaced suffixes, contradictory alias families, untyped malformed metadata, and inconsistent pagination totals. Each has a failing regression and a correction. Further checks bind reviewed alias URNs to live issuance dates, reject discarded historical context on exact citations, validate incompatible signed plans before traffic, and distinguish planned pagination from interruption. The review-fix test replay is recorded on the implementation ticket; no initial passing suite is presented as proof that review found no defects.
